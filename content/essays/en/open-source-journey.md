# My Open Source Journey

Two years ago, I submitted my first Pull Request on GitHub. It was the smallest possible change — fixing a typo in some documentation.

My palms were sweating as I clicked "Create Pull Request."

## The First Merge

That PR was merged within 20 minutes. The maintainer left a single word: "Thanks!" Just one word, but it meant everything to me. It was like a door cracking open, revealing a whole other world of possibilities.

After that, I started contributing more frequently. From fixing docs to fixing bugs, from small features to complete new functionality. Every contribution taught me something new — not because the code was inherently difficult, but because you have to understand architecture in an unfamiliar codebase, follow conventions, and collaborate with people you've never met.

## From Contributor to Maintainer

Last year, I became the maintainer of a VS Code extension. This role shift showed me the other side of open source.

As a contributor, you only worry about your own PR. As a maintainer, you need to:
- Review code from contributors around the world
- Keep documentation and CHANGELOG up to date
- Handle issues (including the vague "why doesn't this work" ones)
- Balance "accept this PR" against "keep the codebase consistent"

It's exhausting sometimes. But seeing people use your project, report bugs, even submit PRs — that satisfaction is irreplaceable.

## The Real Value of Open Source

Many people think contributing to open source is about padding your resume. I won't deny that as a benefit, but it's not the most important one.

Open source taught me:
- **How to read code** — understanding the architecture of a large project is harder than writing new code
- **How to communicate** — expressing technical ideas clearly in writing, which is critical in remote work
- **How to receive criticism** — code review isn't about rejecting you; it's about building better software

If you're hesitating to start contributing to open source, my advice is: start with the tools you use every day. You don't need to become a "core contributor." Fixing a typo, improving documentation, answering an issue — these are all valuable contributions.

The open source community is built from countless small contributions like these.
